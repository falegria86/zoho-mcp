## 2. Detalle por elemento

### 1. Issue 106599000037549184 — No permite cargar archivo en TRM apertura de cuentas condominio
- **Severidad:** Crítico · **Área técnica:** Otros
- **Descripción:** En el paso *Carga masiva de cuentas*, al cargar el archivo y presionar **Guardar**, aparece un mensaje de error (en Producción). En QA no se lograba replicar porque la pantalla se quedaba cargando sin permitir guardar.
- **Causa raíz / solución:** Problema en la librería de lectura del Excel: para el campo *indiviso* se leían valores como `1.631` con demasiados decimales. La solución requiere que las celdas del Excel respeten la cantidad de decimales aceptada por cada campo. Relación de decimales por campo definida:
  - `superficie_total_del_terreno`, `valor_del_terreno`, `area_titulo`, `superficie_de_la_construccion`, `valor_de_la_construccion`, `valor_catastral`, `valor_catastral_calculado` → **3**
  - `tasa` → **6** · `indiviso` → **8** · `frente` → **2** · `profundidad` → **2** · `perimetro` → **2** · `factor_merito_demerito` → **2** · `porcentaje_demerito` → **4** · `porcentaje_traslado` → **2**
- **Revisor de operaciones:** Jorge Ivan González
- **Validación:** Revisado y validado por Operaciones sobre el ambiente QA. Listo para producción.

### 2. Issue 106599000037455043 — Captura de porcentajes con decimales que contienen 0 (Transmisión Patrimonial)
- **Severidad:** Alta · **Área técnica:** Otros
- **Descripción:** En Transmisiones Patrimoniales, paso *Propietarios*, el campo **Porcentaje** no permitía capturar decimales cuyo primer dígito decimal fuera `0` (ej. `45.05`): al escribir el `0` se eliminaba el punto. Valores como `45.15` sí funcionaban.
- **Resultado esperado:** El campo debe aceptar cualquier decimal válido (`45.05`, `12.01`, `99.09`, etc.).
- **Revisor de operaciones:** Jorge Ivan González
- **Validación:** Revisado y validado por Operaciones sobre el ambiente QA. Listo para producción.
